# 重规划有限状态环与配对评测CPU里程碑（2026-09-25）

## 完成内容

在无GPU模式下，将恢复后的π0.5短段执行从runner中的一次性实验整理为独立控制协议。`RecoveryReplanCoordinator`只接收因果证据，不拥有模型、机器人或仿真器，负责四件事：候选计划新颖性审查、短段结果解释、有限重采样/更深回退、硬故障安全停止。

新颖性门不因动作相似本身拒绝计划。只有以下条件同时成立才拒绝：

1. 新计划重新进入已知失败区域；
2. 与失败计划的平均平移方向高度一致；
3. 两条累计路径终点距离很小；
4. 预计恢复进展低于最低要求。

这避免把任务本来就需要重复的接近/抓取动作误判为错误。候选被拒或短段无有效进展会消耗同一有限预算：先重采样，连续失败后要求更早检查点回退；多层预算耗尽才safe stop。安全且有独立进展的短段清零本层失败计数并重新观察；任务成功进入complete；硬故障不等待重试，立即safe stop。

机器可读协议 `HYBRID_RECOVERY_WITH_REPLAN_PROTOCOL_20260925.json` 覆盖12条路径，包括重复失败计划、有效短段、无效短段和重规划硬故障；全部安全断言为true。定向恢复与配对测试68项通过，项目完整回归383项通过。

## “有用进展”的边界

机械臂仍在运动、动作响应方向一致或碰撞风险低，只能说明执行层正常，不能证明任务在恢复。因此 `useful_progress` 必须来自独立任务证据，例如目标物体距离缩短、正确物体仍随夹爪运动、目标关系接近完成或环境任务成功信号。缺少这些证据时不得自动当作false消耗预算，也不得当作true继续无限执行；在线集成应进入补观察/诊断状态。

## 配对评测器

新增严格配对统计模块和JSONL汇总脚本。每一对必须同时记录：任务、初始状态、π0.5采样噪声、扰动身份；缺项或重复pair id直接拒绝。对照组禁用恢复控制权，处理组只改变是否允许恢复，其余条件保持一致。

报告指标包括：

- 对照与处理成功数；
- 基线失败但恢复成功（recovered failures）；
- 基线成功但恢复失败（intervention harms）；
- 配对成功率净变化与bootstrap 95%区间；
- McNemar精确检验；
- safe stop、硬故障和动作开销。

这样可以直接回答“监督器介入是否真的改善成功率，还是让本来会成功的任务失败”，不能只报告处理组成功率。
