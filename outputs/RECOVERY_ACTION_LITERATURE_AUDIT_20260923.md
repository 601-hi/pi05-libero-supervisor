# 异常检测后的具体纠偏操作：文献审计与本项目定位

日期：2026-09-23

## 1. 先区分三个问题

1. **是否异常**：当前执行是否已经偏离正常分布。
2. **为什么异常**：失败属于失配、抓空、抓错、掉落、卡住、目标状态未改变、长期偏离还是其他机制。
3. **如何恢复**：应该重试、回退、重置物体、切换子任务、加入残差动作，还是停止并请求人工处理。

本项目此前在受控 scale 扰动上主要验证了第 1 项；自然 LIBERO 闭环中的主要瓶颈是第 2 项不够可靠，导致第 3 项只能采用“清空动作块、短暂停留、重新请求同一个冻结 π0.5”。因此检测可以有效，而恢复仍可能为零。

## 2. 文献中的恢复动作并不是同一种“重新规划”

### 2.1 原指令重询与阶段提示恢复

VLA-Corrector 保留原任务指令，在报警后丢弃未执行动作块，将阶段相关恢复片段拼接到原指令：

```text
q_recovery = q_original + "Immediate recovery: " + stage_directive
actions = frozen_pi05(current_observation, q_recovery)
execute a short recovery prefix
restore q_original
```

它不是让外部模块直接改动作。监视器从双视角 RGB、8 维本体状态和已执行动作历史估计风险；线上采用阈值、连续四窗确认和冷却。阶段置信不足时退化为通用 `UNKNOWN_FAILURE` 提示。恢复动作最多 100 步，恢复期间以 3 步前缀重新查询，正常执行使用 5 步前缀。

这比本项目当前“原提示重新询问”多了一个真正改变条件分布的变量：**失败阶段/机制提示**。

### 2.2 Continue-or-Replan

BCP 不负责把已经破坏的场景恢复原状。它为动作块的每一个前缀学习 Bernoulli 式“继续还是重新观测并规划”，目标是在接近抓取、闭合夹爪等关键阶段前及时重规划，减少陈旧动作块造成的错误。因此它更像预防性执行时域控制，不是完整的事后纠偏器。

### 2.3 历史清除、检查点回退与状态复位

- RePO-VLA 在构造恢复训练片段时切掉失败前缀，并在纠偏起点清空观测历史，使策略学习“从当前不利状态开始恢复”，而不是继续被失败历史牵引。这主要是训练数据构造方法，不等于部署时能让真实环境倒退。
- Rewind-IL 在线保存或检索语义验证过的安全中间状态。失败后选择最近安全检查点，把机器人/场景恢复到该状态，并从干净策略状态重新推理。仿真中可以精确 respawn；真实机器人必须用可执行的物理回退或重置技能，不能用仿真状态瞬移冒充真实恢复。
- HELM 使用情景记忆、执行前状态验证器和控制器；验证失败时回滚子目标并重规划。如果物理回滚不可行，则从当前损坏状态生成向前恢复计划。

### 2.4 Retry 与对象级 Reset

FLARE 将故障分成两层：分布内姿态偏差由加入扰动和桥接片段训练出的 VLA 自行 Retry；环境已经进入分布外状态时，视觉语言监视器识别需要恢复的对象并切换到小型对象级 Reset 技能。Reset 完成后再回到原任务。关键不是重复原策略，而是先把环境恢复到任务仍可继续的状态。

### 2.5 子任务回溯与里程碑恢复

- CycleVLA 在子任务边界预测失败，回退到能够重新满足缺失前提的最早子任务，然后让 VLA 基于当前真实场景重新感知和重试。它不恢复物体状态，而是恢复任务逻辑前提。
- B2FF 在干净初始状态预先生成一组“熟悉未来”视觉里程碑。失败后不再从离轨状态自由想象未来，而是选择最可恢复的既有里程碑，把它作为固定视觉目标驱动冻结 VLA。候选偏移覆盖 rollback、retry 和 skip-ahead；选择器用离线反事实 rollout 的最终成功标签训练。

### 2.6 反事实几何再对齐

CoRe 从最近可行锚点出发，用合成观测让冻结 VLA 在不进行物理试错的情况下想象在当前目标下应如何继续；再求一个尽量小的机器人/场景物理再对齐计划，使真实状态重新接入这条想象轨迹，随后把控制权交还基础策略。它强调的是“回到策略熟悉流形”，而不是在任意失败状态持续重询。

### 2.7 残差动作专家

ReCoVLA 冻结 π0.5，外部 VLM 从失败 rollout 生成结构化描述：失败类型、恢复阶段、活动实体、置信度和奖励项掩码。确定性奖励编译器把这些字段转成带阶段门控的奖励，用于训练对应失败类型的残差策略：

```text
a_base, h = frozen_vla(observation, instruction)
failure = vlm_failure_descriptor(history)
if failure.category is known:
    a_residual = residual_expert[failure.category](h)
    a_exec = clip(a_base + a_residual)
else:
    a_exec = a_base
```

“放置”等奖励只有在“重新抓稳”后才激活，以避免奖励投机。它是真正修改低层动作的恢复器，但成本明显高于提示恢复，需要失败分类、仿真奖励和每类残差策略训练。

### 2.8 语言监督器与恢复 actor

RACER 的 VLM 每一步结合图像、上一条细粒度指令、任务目标和机器人状态变化，判断上一指令是否完成或发生可恢复失败，并输出下一条具体语言指令；经过恢复数据训练的 actor 再执行。它不是把自然语言直接当安全动作，而是要求 actor 见过“失败状态 + 纠偏语言 + 正确动作”的配对训练数据。

## 3. 对本项目最现实的主线

### P0：把现有闭环变成可比较的恢复基线

冻结检测器和测试清单，统一比较：

1. 无干预；
2. 仅清动作块并用原指令重询；
3. 清动作块 + 当前状态重询 + 短执行时域；
4. 机制/阶段提示 + 短执行时域；
5. 机制提示 + 一个安全几何原语（松夹、抬升、退离、重新接近）；
6. 对不可恢复或低置信度故障安全停止。

### P1：先补机制路由，不立刻训练重型残差策略

视觉与运动学证据只需要先可靠区分少量动作上真正不同的分支：

- 抓空/未附着：松夹、退离、重新接近并抓取；
- 掉落：回到目标物当前视觉位置重新抓取；
- 固定障碍/卡住：停止沿当前方向施力，抬升或沿相反安全方向退离；
- 抓错：放置到安全区，重新定位正确目标；
- 长期目标偏离/策略停滞：改用阶段提示或视觉里程碑，而不是再次发送同一原提示；
- 未知高风险：停止，不强行恢复。

### P2：再比较提示、里程碑和残差三种恢复等级

- 提示恢复：最快、最适合作为当前主线；
- 里程碑/子任务回溯：需要任务进度表示，但能处理“动作都合理却始终到不了目标”；
- 残差专家：能修低层动作，但需要更多失败数据和训练资源，适合作为后续增强而不是第一版框架的阻塞项。

## 4. 以前 LIBERO 识别结果的严格解释

### 4.1 受控执行扰动（seed21，同集冻结评价）

| 指标 | 双专家 | 重建旧 v2 二分类 MLP |
|---|---:|---:|
| 实际异常 episode 检出 | 50/57 = 87.7% | 40/57 = 70.2% |
| 正常 episode 误报 | 1/23 = 4.3% | 2/23 = 8.7% |
| 扰动 active-step recall | 71.1% | 49.1% |
| 非扰动 inactive-step alarm rate | 0.832% | 0.737% |

双专家相对重建旧 v2 的配对结果为：双双检出 39、仅双专家 11、仅旧 v2 1、双双漏检 6；McNemar 精确双侧检验 `p=0.00635`。这支持双专家在已知的平移响应衰减扰动上更敏感，但旧 v2 没保存原始权重和完整标准化参数，因此对照对象是确定性重建基线，不是原 checkpoint。

### 4.2 自然 LIBERO 闭环失败

- 30 对 baseline/control 合计成功数都是 22/30；恢复成功为 0/8。
- Stage-1 的 20 个自然成功任务全部保持成功，但 6 个成功 episode 也触发了 9 次 `policy_stall` 重规划。
- Stage-2 的 8 个自然 baseline 失败中，6 个产生了重规划或安全停止，表面覆盖率是 75%；但告警主要是通用停滞，不是带真值验证的失败机制分类。
- 4 个失败被安全停止，2 个重规划后仍超时，2 个未达到明确干预条件。
- 执行双专家没有在这些自然任务上产生可行动的 `execution_mismatch`。

因此不能把 `6/8` 称为“自然异常识别准确率 75%”。它只是**粗粒度干预覆盖率**。自然失败集合没有逐步机制真值，且成功 episode 也会触发停滞告警，所以精确率、机制分类准确率和时序定位准确率均尚未建立。当前可以成立的说法是：

> 受控执行衰减的检测已经达到 87.7% episode recall，并保持较低正常 episode 误报；但向自然任务失败迁移后，监督器主要能发现部分“过程停滞”，尚不能可靠解释失败机制，也没有产生任务救回。

## 5. 后续评价指标

以后必须同时报告：异常 episode recall、正常 episode false-alarm、首次报警延迟、机制分类混淆矩阵、恢复成功率、损害率、恢复动作成本、失败后节省步数，以及相同 seed/扩散噪声下 baseline-control 的成对最终成功差异。只有检测率而没有最终任务结果，或只有最终成功而没有报警质量，都不足以说明纠偏器有效。
