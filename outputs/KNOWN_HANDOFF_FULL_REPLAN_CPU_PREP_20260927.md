# 已知成功汇合场景的完整重规划 CPU 准备（2026-09-27）

## 为什么改变实验顺序

最新五对视觉触发闭环中，四条失败都被视觉关系监督器选中，唯一成功回合没有被介入；但四条均未完成回退，所以 π0.5 从未获得回退后的完整执行窗口。继续只调逃逸器，会把“恢复控制器能否汇合”和“汇合后重规划是否有用”两个问题长期绑在一起。

因此先选择此前已经真实完成六维汇合、倒序回放并进入 `reobserve_and_replan` 的固定场景，单独验证后半链：

- `libero_spatial/task0`，seed 7；
- 执行已知成功轨迹前 60 个动作；
- action 20 为汇合状态，action 10 为倒序回放终点；
- 该场景此前用 126 个逃逸步完成恢复；
- 恢复起点末端位置和四元数与源轨迹 action 59 的执行后状态逐值一致。

该试验使用人工注入的恢复请求和已知成功历史，因此只验证恢复后的连续接管能力，不代表自然异常检测率，也不能报告为监督器相对 baseline 的救回率。

## 本次补齐的能力

`scripts/run_closed_loop_hybrid_recovery_smoke.py` 原先只执行 π0.5 返回的第一个策略动作，因而只能证明控制权移交，不能判断任务是否能完成。现在改为：

1. 恢复端口只有进入 `replan_pending` 才允许请求 π0.5；
2. 可固定采样噪声 seed，并为每次推理记录噪声哈希；
3. 动作块执行完或响应监测请求重新规划时，重新观察并请求新动作块；
4. 每个策略动作仍拆成安全微步，每步通过运动学前门与碰撞门；
5. 响应异常可请求新块或安全停止；
6. 任务成功、动作预算、推理预算和安全停止均为明确终止条件。

冻结 GPU 脚本为 `outputs/run_known_handoff_full_replan_gpu_20260927.sh`。预算分别为 escape 180、replay 260、重规划策略动作 220、最多 50 次推理；这些是有限预算，不允许用无限重试制造成功。

## 视觉证据与重规划证据分开陈述

现有 task0 close-drawer 五对严格配对试验提供的是视觉路由证据：四条 baseline 失败均由视觉关系异常触发恢复，唯一 baseline 成功回合未介入并保持成功。它支持“视觉能在这个冻结小样本中选择需要恢复的回合”，不支持“视觉已经实现跨任务泛化”。

本次 spatial 场景提供的将是后半链证据：已知恢复完成后，连续 π0.5 重规划是否能完成任务。两者场景不同，暂不拼接成虚假的单次端到端成功。若后半链成立，下一阶段才把已验证的视觉入口与已验证的恢复后接管组合起来，再做严格配对的真实救回测试。
