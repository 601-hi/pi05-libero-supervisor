# 回退 MVP：轨迹邻域交接与重规划新颖性门（2026-09-28）

## 为什么改

GPU v8 的四条失败轨迹均未进入真正的重规划。主要原因不是 π0.5 重规划已经被证明无效，而是回退前端把大量正常历史点因“动力学可靠性未知”排除，并要求逐点精确倒序回放。该标准把模型不知道与物理危险混为一谈，也让系统在任务截止前长期停留于 JOIN/REPLAY。

本阶段目标是先形成可证伪的端到端 MVP，不追求回退器一次达到最终最优。

## 修改一：未知可靠性不再自动等价于危险

开启 `supervisor_rollback_mvp_near_trajectory_enabled` 后，最近历史点若动力学可靠性缺失，可以按低置信先验进入候选集；但接触明确不安全、观测不可用、关节/碰撞硬约束不合格仍会拒绝。即：

> unknown 允许谨慎使用；unsafe 仍禁止使用。

这不是关闭碰撞门，也不使用任务成功标签挑点。

## 修改二：进入已认证历史轨迹管道即可重新观察

旧逻辑要求完成整段倒序回放后才进入 `REPLAN_PENDING`。MVP 新逻辑允许 JOIN 末端进入已认证历史轨迹点的位置—姿态邻域后立即交回 π0.5：

\[
\|p-p_h\|\le\varepsilon_p,\qquad
d_R(R,R_h)\le\varepsilon_R.
\]

容差由 CLI 显式配置，默认仍关闭该 MVP 开关。碰撞候选生成、逐微步检查和硬停止均保持有效。

## 修改三：重规划新颖性门

新模块 `vla_supervisor/replan_novelty.py` 比较原失败动作块与回退后的新动作块，联合使用：

- 六维动作相对 L2 差异；
- 逐步方向余弦的中位数；
- 累积六维方向余弦；
- 夹爪符号一致率。

只有四项共同支持“几乎重复”才拒绝。证据缺失时第一版 fail-open，避免日志或短动作块让系统死锁。重复时不执行该块，而是 `rollback_level += 1`，尝试更早的兼容历史锚点；达到层级上限或没有更早锚点则安全停止。新计划发生实质变化时才完成控制权交接，后续重新接受正常双专家和视觉监督。

必须强调：新颖性门只证明“计划变了”，不证明“计划正确”。正确性仍需由执行一致性、安全门、任务后果监督和最终任务结果共同检验。

## 验证

- 新颖性门单元测试：3 passed；
- 历史点与轨迹邻域定向测试：51 passed；
- 无卡完整回归（排除当前环境缺少可选依赖的3个测试文件）：432 passed；
- `monitoring_main.py` 语法及新增 CLI 参数检查通过。

## 下一步（需要 GPU）

用同一 π0.5 服务生命周期、固定初始化与固定扩散噪声跑少量严格配对：旧控制与 MVP 控制。先验停止条件为：

1. 介入前物理前缀不一致则该配对作废；
2. 检查四条原失败是否至少进入 `REPLAN_PENDING`；
3. 检查 `replan_novelty` 的 repeated/changed 以及更早层级升级；
4. 最终同时报告 benchmark success、人工/关系过程有效性、救回、误伤和安全停止，不能只报 LIBERO 终态位。
