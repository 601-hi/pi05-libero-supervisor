# MuJoCo候选扫掠碰撞Oracle里程碑

日期：2026-09-25

## 目的与边界

本节点用MuJoCo完整几何验证“碰撞风险主导的安全脱困候选评分”是否具有正确排序行为。`mujoco.mj_geomDistance`读取的是仿真隐藏几何，只能作为评测oracle，绝不作为可部署监督器的传感器输入或创新性证据。正式系统仍需机器人碰撞模型、环境标定、视觉占用、力矩或触觉提供等价观测。

## 实现

- 对当前仿真状态做完整保存；
- 用阻尼最小二乘Jacobian预测每个2–5 mm末端候选对应的关节变化；
- 在当前和预测关节状态间插值7个样本；
- 查询每个样本的机器人自碰和机器人—环境有符号几何距离；
- 输出起点、整段最小值、终点距离及产生最小距离的几何对；
- 最后恢复完整仿真状态并验证逐值误差为0。

过滤规则只排除明确不应计分的结构几何：`contype=0`的非接触代理、三层身体树以内的相邻连杆重叠、以及固定底座与安装座的永久重叠。移动连杆、夹爪、桌面、物体和其余环境几何仍参与查询。

## 发现与修正

第一版错误地把腕部—夹爪结构重叠和非接触手指代理当成碰撞，所有候选风险接近1。第二版仍把固定link0与pedestal的安装重叠当成环境碰撞。逐一通过身体树、`contype`和实际接触对审计后修正，未通过放宽风险阈值掩盖。

多阶段评估又发现：第40、60、70步已经存在桌面或碗的接触/近接触。若只取扫掠绝对最小距离，所有候选都会继承起点接触并被拒绝。因此证据协议改为：

- 当前没有接触时，仍按整段最小保守距离判断新碰撞；
- 当前已经低于安全余量时，比较终点与起点距离，候选加深接触则风险上升，沿分离方向缓解接触则风险下降；
- 仍保留硬拒绝和`no_viable_candidate`输出，不能强行选择全体危险候选。

汇合评分同时补入相对进展，避免绝对误差尺度过大导致hold永远最优。

## 四阶段结果

在同一条成功task0轨迹的prefix 20、40、60、70处，各评估22个候选：

- 可行候选数：22、17、18、18；
- 所有候选评估前后仿真状态恢复误差：0；
- prefix20：脱困完成度0选择hold，0.5和1选择朝历史状态5 mm；
- prefix40：已有深接触，低权重阶段选择能缓解接触并靠近历史的3.5 mm方向；
- prefix60：抓取附近整体风险较高，选择当前最能改善接触/管道证据的向下5 mm候选；
- prefix70：早期选择hold，后期切换为朝历史状态5 mm。

这些只证明评分器在oracle几何下能够区分新碰撞、加深接触和缓解接触，不证明选择的动作已经能恢复任务，也不证明对应风险已在真机校准。

定向测试21项、完整回归339项全部通过。GPU上没有遗留策略或计算进程。
