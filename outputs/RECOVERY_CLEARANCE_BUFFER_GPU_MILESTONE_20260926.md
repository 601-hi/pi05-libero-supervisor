# 回退碰撞缓冲与安全退化 GPU 里程碑（2026-09-26）

## 本轮要回答的问题

在修复检查点准入语义后，只重跑此前受伤的 LIBERO Spatial task 4，验证三个条件：正常前缀能否保存安全点、检测能否把控制权交给复杂回退、回退是否会伤害原本能够成功的任务。

## 发现一：历史点已经存在，旧瓶颈已解除

动作 40--79 平移置零的冻结实验中，在线链路保存了 action 20、23、27 三个安全检查点，并进入 `complex_rollback`。这说明此前“没有历史点”确实来自可靠度与接触定义错误，而不是任务天然没有安全状态。

但回退只执行一步便停止。第一候选的预测环境间隙为 `+0.768 -> +0.200 mm`，实际执行后的下一状态却为 `-3.229 mm`；第二候选还会继续加深接触，扫掠门正确拒绝。进一步确认动作 40--79 的故障仍在生效，第一回退动作的平移也被置零，因此该实验只能证明持续执行器故障下系统会安全停止，不能要求它成功回退。

## 发现二：有限故障暴露碰撞预测不确定性

动作 40--49 的有限故障被 π0.5 自身吸收：基线和监督器均成功且监督器不介入。这支持“可自行恢复的扰动不应被强制纠偏”。

随后只作工程边界探针，将故障冻结为动作 40--52，使执行器在预期回退前恢复。监督器在 action 53 进入回退，但同一个候选仍从预测 `+0.200 mm` 变成实际约 `-3.088 mm`；旧规则只要求预测终点为正，因此允许了一个没有模型误差余量的亚毫米贴边动作。基线成功而监督器失败，这是一条明确的有害干预，不得包装成恢复收益。

## 修复：缓冲区内只能增加间隙

新门控不采用简单的固定 5 mm 禁区，而区分两种情况：

- 预测终点保留至少 5 mm 缓冲时可以接近障碍；
- 当前或预测状态位于缓冲区内时，候选必须严格增加有符号间隙；
- 已有穿入允许分步逃逸，但不得加深；
- 缺失、非有限距离一律拒绝。

若候选被拒绝，它尚未执行，因此系统不再终止整条 episode，而是保持当前位置、归还控制权，要求 π0.5 用新观测重新规划。新增边界测试后完整回归为 440 项通过。

## 同一冻结对照复测

复测仍使用相同 task、环境种子、采样噪声和动作 40--52 故障：

- baseline：成功，132 步；
- supervisor：成功，120 步；
- 动作 0--52 的 intended/executed action 与末端位姿完全一致；
- action 53 候选因环境间隙预测 `0.768 -> 0.200 mm` 被提前拒绝；
- `rollback_executed_steps=0`，危险动作未执行；
- 随后重新观察规划并成功，比基线少 12 步。

这证明“检查点准备—回退候选—保守碰撞拒绝—安全退化到策略重规划”链路可用并消除了该样本上的伤害；它尚未证明倒序回放本身提高任务成功率。动作 40--52 是根据机制边界选择的工程探针，不能放入最终无偏效果统计。

## 下一步

下一阶段在 CPU 上实现缓冲区内的多方向/多尺度逃逸候选搜索，使系统在直接朝历史点不安全时优先寻找增加碰撞间隙的微步；通过单元测试后再用 GPU 做一次冻结验证。不能通过放宽扫掠门获得回退成功。
