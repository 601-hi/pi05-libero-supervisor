# 动态逃逸—历史趋近权重 CPU 里程碑（2026-09-27）

## GPU失败所揭示的问题

三段式检查点和真实MuJoCo geom ID修复后，LIBERO-90 task0首次真实进入复杂回退，说明“零检查点”问题已经解决。但320步全部停留在`join`状态并耗尽预算，任务仍失败。回退开始时距action42汇合点10.13 mm，结束时扩大到44.55 mm；净回退运动34.74 mm，却主要远离历史轨迹。320步中255步选择`+Y, scale=0.25`。

直达候选被拒绝具有物理依据：它会重新靠近柜体，低于5 mm模型误差缓冲。错误发生在通过硬门后的软排序。旧排序在所有时刻都先最大化最差间隙增益，再用历史方向一致性破平，因此即使已经脱离接触区，也会无限选择最能远离柜体而非最能回归历史轨迹的方向。这证明用户先前提出的动态权重尚未真正实现。

## 新选择规则

硬门完全不变：不安全候选不参与排序，安全权重无法覆盖碰撞拒绝。安全直达候选仍优先，并选择允许的最大尺度。只有所有直达候选均失败时，才在最小尺度的安全轴向候选之间计算：

\[
J_i=(1-w)\,\widetilde{g_i}+w\,\frac{1+\cos_i}{2}
\]

其中`g`为候选最差间隙增益并在同组内归一化，`cos`为候选平移方向与历史汇合方向的余弦。权重由当前最小安全余量连续决定：

\[
w(d)=\sigma\!\left(\frac{d-4.5\mathrm{mm}}{0.5\mathrm{mm}}\right)
\]

接触附近`w≈0`，优先脱险；接近5 mm缓冲时平滑转移；超过约6 mm时`w>0.95`，优先减少历史误差。4.5 mm中心来自既有5 mm模型误差缓冲，而不是LIBERO任务标签。

## 冻结日志反事实重放

在不改变安全候选集合的前提下，对GPU保存的6720条候选、320个决策点重放：

- 旧选择中正向历史一致候选51/320；新选择223/320；
- 173/320个决策改变；
- `+Y`从255次降至96次；
- `+Z`从34次增至176次；
- 高安全余量尾段开始混合选择正向`+Z`、`-Y`以及安全直达，而非持续单向逃逸。

这只是固定旧状态上的反事实排序验证，不能证明新闭环一定收敛；新动作会改变后续状态和候选集合。代码新增低间隙优先安全增益、高间隙优先历史方向的单元测试，完整回归449/449通过。在线proposal日志新增`history_progress_weight`，下一GPU可以审计实际权重转换。

## 下一实验边界

下一GPU仍只复验同一个已确认自然失败的task0开发身份。成功标准依次为：不违反逐碰撞对硬门；不再320步停留在join；汇合距离总体下降并进入replay；最后才看任务成功。若仍失败，先检查闭环路径几何，不通过增加回退预算掩盖问题。
