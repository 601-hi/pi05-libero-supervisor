# 多方向逃逸 GPU 机制验证（2026-09-26）

## 测试边界

本轮只验证冻结的LIBERO Spatial task 4机制探针，不估计检测率或最终成功率。自然监视器在服务器重启后的首次运行没有再次触发stall，说明固定环境seed和π0.5扩散噪声仍不能保证跨GPU服务重启的整条闭环位级复现。为避免反复运行直到偶然触发，后续使用正式脚本已有的test-only事件：action 50--52注入三帧`policy_stall`，让2-of-3融合在固定时刻移交恢复；物理扰动仍为action 40--52平移执行置零。测试事件只控制触发，不提供候选方向或碰撞答案。

## 控制链结果

测试最终成功，共177个动作；其中40步由复杂回退器执行，随后完成一次π0.5重规划。每个回退周期评估21个候选，共840次候选扫掠；373个通过当前硬门。最终选择分布为：

- `direct_1.0`：35次；
- `direct_0.5`：4次；
- `escape_axis_1_pos_0.25`：1次。

状态先执行23步6D汇合，再执行17步倒序回放，然后把控制权交回策略。action 76是首次实际使用新多方向机制：所有优先直达方案不再合适，系统选择约0.75 mm等效步长的+Y轴逃逸候选。由此证明候选生成、逐候选门控、排序、执行、继续回放和重规划链路在真实在线脚本中全部贯通。

## 关键负结果：全局最小距离不可作连续接触状态

加入候选几何体对和执行后实测间隙日志后发现，环境最小距离的大跳变主要对应最近几何体对切换，而不是同一接触对连续变化。例如action 76：

- 预测最小对：`gripper0_hand_collision`与`wooden_cabinet_1_g9`，距离预测为`-0.734 -> -0.518 mm`；
- 执行后最小对：`gripper0_finger2_pad_collision`与`wooden_cabinet_1_g11`，全局最小距离变为约`-70.47 mm`。

相邻步骤还反复在hand、finger1、finger2以及柜体g9/g11/g12、黑碗几何之间切换。当前oracle把任务允许接触、柜内接近和潜在危险碰撞都压缩成“全局最小有符号距离”。不同几何体对的两个标量不可直接比较，因此不能据此宣称轴向逃逸使真实碰撞连续改善；任务最终成功也不能反向证明这些接触安全。

## 结论与下一步

本轮证明多方向回退控制链可执行，但否决了“仅用全局最小距离评价碰撞改善”的安全解释。下一步必须在CPU上改为按几何体对追踪：保存候选前每一条近接触/穿入对及距离；已有接触对只能保持或改善；任何新出现的深接触对应拒绝；距离足够远的对不必全部记录。不能把整个柜体或目标物体简单白名单化，因为同一物体既可能是允许接触，也可能是危险撞击对象。
