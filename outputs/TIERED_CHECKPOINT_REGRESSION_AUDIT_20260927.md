# 三段式历史检查点回归审计（2026-09-27）

## 为什么早期回退成功、自然失败却完全没有回退

最初在 LIBERO Spatial task 4 上验证成功的是“已有检查点条件下的在线控制链”：40 个复杂回退动作、一次轴向逃逸、倒序回放和 π0.5 重规划全部贯通。该结果证明执行器和候选安全门可工作，但没有证明检查点准入可以跨任务泛化。

LIBERO-90 task 0 的自然失败暴露了两个不同问题。第一，条件动力学专家没有为该域给出可用可靠度，所有历史点均出现 `response_reliability=None`。第二，碰撞日志仍把约 -30 mm 的机器人底座—安装座固定装配重叠作为环境最小距离。旧检查点契约要求每个字段都完整且 `contact_clear=True`，因此 0--54 步全部拒绝，回退执行数为零。监督器虽然在第 54、71、84 步正确检测停滞，却只能原地保持并重规划，最终在第 98 步安全停止。

这说明最近修复中存在“正确安全原则被错误扩张”的问题：逐个即将执行的回退微动作确实应严格验证，但久远历史状态只是导航参考，不应因专家拒识或固定装配接触而全部消失。逐碰撞对候选门本身应保留；需要重设的是历史参考点准入，而不是削弱实际动作安全门。

## 三段式准入

以首次故障动作 `F` 为时间尺度，而不是写死某个 LIBERO 步数：

- 早期可信段 `[0, 0.4F)`：只要求位姿/关节状态有限、关节与奇异性硬裕度通过、没有相对启动基线新增或恶化的碰撞。动力学专家缺失不构成拒绝。按三步间隔保存，确保启动安全前缀提供多个参考点。
- 中段宽松段 `[0.4F, 0.8F)`：在硬运动学条件上加入相机健康度 `>=0.5`；若动力学可靠度存在则要求 `>=0.15`，若专家拒识则保留为未知而非异常；碰撞仍不得相对结构基线恶化。
- 近期严格段 `[0.8F, F)`：要求相机健康、标定动力学可靠度和接触证据全部通过。这里靠近失败状态，继续保持保守。

启动前五个状态中反复出现、深度在 0.1 mm 内不恶化的同一最小碰撞对被标记为结构装配基线。该豁免不随物体名称扩散：几何体对变化、新增穿入或穿入加深均不能继承。

三段策略只决定哪些历史状态可作为参考。每个实际回退微动作仍必须经过指令安全门、MuJoCo 扫掠碰撞门、逐碰撞对门和执行后响应检查，因此“保证有参考点”不等于“保证盲目执行”。

## 回归保护

新增测试覆盖：

1. 专家在整段轨迹输出未知、但固定装配对稳定时，早期和中段仍能形成足够参考并完成恢复计划准备；
2. 后半段出现新的手掌—柜体深碰撞时，新碰撞点不能因早期结构基线而获准；
3. 原严格检查点路径继续优先，不改变已有完整证据场景。

无卡服务器验证已完成。定向测试 28/28、完整回归 448/448 通过。对昨天同身份 task 0 自然失败轨迹的前 54 步离线回放得到 15 个参考点，其中早期可信段 8 个、中段宽松段 7 个；恢复准备状态由原来的 `insufficient_admitted_checkpoints` 变为 `ready`，汇合点为 action 42，目标点为 action 15，倒序参考序列为 `42,39,...,15`。近期严格段没有伪造可靠度，保持零候选。

## 同时发现并修复的 MuJoCo ID 错位

旧 oracle 使用 `enumerate(model.geom_names)`，错误地假设名称表位置就是真实 geom ID。当前 robosuite/mujoco-py 绑定的 `geom_names` 是紧凑名称表，不与 ID 对齐：实测名称表第24项为 `robot0_link0_collision`，但 `geom_id2name(24)` 实际是 `robot0_g8_vis`。因此源码虽然写了底座排除，运行时却排除了另一个几何体。

修复后改为遍历 `range(model.ngeom)` 并逐 ID 调用 `geom_id2name`。同一 LIBERO-90 task 0、seed34 初始状态的 oracle 结果从错误的环境最小距离 `-30.032 mm`（底座—安装座）变为 `+46.960 mm`（手指垫—柜体），并确认底座不再位于活动机器人几何集合。新增紧凑名称表与真实 ID 故意错位的回归测试，防止该问题再次出现。

因此本轮不是简单“放宽阈值”：先修复了碰撞测量对象错误，再以失败相对时间实现分层历史信任，同时保留每个实际回退微动作的严格逐碰撞对门。下一步才允许重新打开 GPU 做一次同身份配对试验。

## π0.5 VLM 主干目标定位结论

该方向没有“成功成为可用目标定位器”。源码审计确认 π0.5 的图像和语言通过 SigLIP/PaliGemma 表征共同影响动作，旁路也能导出每个相机 4×4 空间 latent；但正式接口不输出对象框、对象类别概率、文本回答或经过校准的语言—区域匹配分数。因此不能从动作模型内部直接读取“目标在这里”。

Grounding DINO 在 57 张有精确标签的观测中给出 48/57 的目标候选覆盖，但覆盖不等于正确定位，许多图存在多候选、整段机械臂框和错误物体。冻结 latent 探针和动作条件视觉残差也曾在开发集有排序信号，却在独立 seed 上产生大量正常误报。当前结论是：π0.5 表征可用于提出或重排候选，不能独立承担安全关键目标定位；该分支必须保持 shadow，不能宣称已经成功。
