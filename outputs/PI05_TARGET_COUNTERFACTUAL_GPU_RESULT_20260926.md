# π0.5 目标候选反事实试验（GPU结果，2026-09-26）

## 目的与预注册判据

本试验只回答一个窄问题：能否不训练额外语义模型，而用冻结的 π0.5 对 SAM2 候选区域的动作敏感性来稳定选出任务目标。

对每个候选掩膜分别做高斯模糊和中性颜色填充，在相同观测状态、任务语言及固定扩散噪声下重新推理，以前 5 步、7 维动作的 RMS 变化作为候选分数。只有两种扰动的 Top-1 相同且最小领先幅度不低于 0.02，才允许输出候选；否则必须弃权。这个分数只是因果动作敏感性，不是目标属于该区域的概率。

## 结果

3 个跨任务近接触样本全部弃权（0/3接受）：

- task31（黑碗）：模糊 Top-1 为候选3，填充 Top-1 为候选0，最小间隔 0.00178。候选3是柜体/抽屉侧区域，候选0覆盖大块台面与机械臂；被夹爪严重遮挡的黑碗没有形成可靠独立候选。
- task58（番茄酱）：模糊 Top-1 为候选0，填充 Top-1 为候选6，最小间隔虽为0.15803，但 Top-1 不一致。人工核对显示候选0覆盖大块桌面、托盘和机械臂，候选6是夹爪下方物体；番茄酱候选约为候选5但两种分数都很低。
- task85（白色杯子）：模糊 Top-1 为候选2，填充 Top-1 为候选6，最小间隔 0.00267。候选2是黑色狭长物，候选6是夹爪下方区域；目标在近接触/遮挡状态下同样没有稳定胜出。

因此，两种遮挡操作改变了不同的图像统计，π0.5 的动作变化会同时响应背景、机械臂、障碍物、容器和被控物体。直接把“动作变化最大”解释为“这里是语言目标”不成立。近接触帧还暴露出一个独立问题：若 SAM2 初始化太晚，目标常被夹爪遮挡，候选集合本身就可能不含完整目标。

## 工程问题与修复

首次运行完成推理后，JSON 写出因 NumPy `int64` 候选编号失败。已在输出边界加入 `descending_ranking()`，逐项转换为 Python `int`，并新增 JSON 安全回归测试；聚焦测试为 3 passed。

## 决策

按预注册规则，停止把 π0.5 动作反事实敏感性作为独立目标解码器，不扩大样本、不训练探针。它未来最多只能作为弱证据，与较早时刻的目标初始化、语言条件开放词汇定位和时序追踪交叉验证；不能单独驱动安全干预或回退。

完整数值见 `PI05_CANDIDATE_COUNTERFACTUAL_PILOT_RESULTS_20260926.json`，三幅候选图见 `pi05_candidate_counterfactual_montages_20260926/`。试验后已关闭 π0.5 服务，端口8000和GPU均为空。
