# 视觉目标生命周期最小闭环（CPU节点，2026-09-26）

## 为什么需要这一层

现有代码已有语义候选选择、SAM2候选关系、受控物体选择和控制—目标融合，但缺少目标身份从“初始化”到“操作中遮挡”的统一生命周期。若直接逐帧选择最高分，夹爪遮挡或分割编号变化时可能把背景、容器或另一个物体偷偷替换成目标；这比明确输出未知更危险。

新增 `vla_supervisor/target_track_lifecycle.py`，作为与具体机器人和LIBERO任务名称无关的保守状态机。

## 数据流与规则

1. 语义定位只允许在操作开始前进行。
2. `SemanticGoalSelector` 必须连续若干帧选择同一候选，才锁定目标身份。
3. 锁定后由跟踪器维持该身份；跟踪置信度不足时进入短暂遮挡状态。
4. 遮挡时可以保存身份记忆，但不向下游输出可执行语义分数。
5. 遮挡超过预算则进入 `lost`。
6. 跟踪器指向另一候选时进入 `identity_conflict`，禁止自动换目标。
7. 若操作开始前未锁定目标，之后即使出现高分候选也只输出 `unavailable_after_manipulation`，避免利用执行后画面重新解释任务。
8. π0.5反事实候选只写入诊断字段，角色固定为 `diagnostic_only_not_identity_evidence`，不能改变锁定结果。

状态机只有在目标当前可靠时才通过 `semantic_scores()` 向既有 `fuse_control_and_goal()` 提供分数。因此：目标可靠且受控物体一致时可得到 `target_controlled`；同一目标短暂遮挡后只会得到 `ambiguous`，不会被误判成抓错目标或任务失败。

## 验证

- 覆盖早期连续确认、禁止晚期初始化、身份冲突不切换、短遮挡与超时丢失、语义歧义重置确认、与控制—目标融合器的端到端接口。
- 聚焦测试：15 passed。
- 完整CPU回归：420 passed，8.61秒。

## 当前边界和下一步

这一节点完成的是安全的数据契约和状态机，不代表开放词汇目标定位准确率已经解决。真实在线候选提供器仍需在较早、低遮挡帧产生语义证据；证据不足时整条视觉分支必须保持未知。下一步应优先用已有轨迹离线回放验证：目标是否能在夹爪闭合前稳定锁定、SAM2能维持多久，以及它与受控物体选择器结合后能否正确区分 `target_controlled`、`wrong_object_control` 和 `ambiguous`。只有该回放通过，才值得再次开启GPU做新的视觉推理。

## 既有三批轨迹的离线跟踪完整性审计

随后复用了三批盲化人工目标候选标注和对应的双向SAM2轨迹，不读取任务结局或扰动标签。60条记录中56条能够对应人工目标候选；以闭爪前16帧和闭爪后10帧为窗口，在候选可见率、质心可见率、相对面积0.20–5.0及单帧质心跳变不超过图像尺度对应阈值的透明完整性门下，47条至少有一个已标注目标候选通过，即已审计样本的83.9%。分批结果为15/20、16/20、16/20。

失败审计表明主要问题是接触遮挡时掩膜面积塌缩到闭爪参考的4%–19%，而非普遍的大幅质心乱跳；另有4条缺少可对应标注或轨迹。为此新增分辨率无关的 `target_track_quality.py`：根据相对面积、空掩膜和按图像对角线归一化的帧间质心跳变输出工程质量分。该分数不是语义正确概率；低质量结果应传给生命周期状态机作为不可用/遮挡，不得继续产生目标位置。

离线审计结果保存在 `ANNOTATED_TARGET_TRACK_INTEGRITY_AUDIT_20260926.json`。新增质量门与审计测试后，完整CPU回归为428 passed。
