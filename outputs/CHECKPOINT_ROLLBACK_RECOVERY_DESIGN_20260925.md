# 可信检查点回退与失败计划拒绝设计（2026-09-25）

## 核心原则

回退恢复机器人状态，不假设世界可逆：

`(q_bad, world_new) -> (q_safe, world_new)`。

π0.5只在到达安全、可观察的恢复区域后重新负责任务规划。检查点选择、回退路径、安全批准和候选拒绝由独立恢复层完成。

## 组件边界

1. `CheckpointBuffer`：只保存经过正常动力学、无异常接触、关节/奇异性余量和可观测性门控的实际状态。
2. `CheckpointSelector`：按异常机制筛选阶段兼容检查点，再综合距离、风险、任务回退成本、可观测性和历史可靠性排序。
3. `RollbackPlanner`：把历史实际状态变成稀疏路标，不倒放历史动作。
4. `RollbackController`：通过现有笛卡尔增量接口生成限幅小步。
5. `RecoverySafetyGate`：每步执行前后检查；硬故障安全停止，软故障重新规划回退路径。
6. `PlanNoveltyGate`：只有新候选重入失败局部、与失败关键片段高度相似且没有恢复进展时才拒绝，避免把必要的重复接近动作误杀。

## 动力学职责

- 回退层生成平滑、限幅、经安全审核的参考运动；
- robosuite操作空间控制器把参考运动转换为低层控制输入；
- MuJoCo求解刚体动力学、约束和接触响应；
- MuJoCo不会自动保证路径安全，监督器仍负责限位、奇异性、碰撞、跟踪误差和意外接触监测。

## 初版验证顺序

1. CPU：检查点准入、选择、逐级回退、路标生成、计划相似性门控的单元测试。
2. GPU/LIBERO：只验证无障碍历史走廊回退能否稳定到达检查点，暂不同时打开语义恢复。
3. 配对闭环：baseline、原地重规划、检查点回退重规划三臂固定初态与扩散噪声比较。
4. 报告救回、破坏、无法回退、安全停止、重规划次数和额外步数，不只报告检测率。

## 既有轨迹可用性审计

对 `closed_loop_v1_libero90` 的10条控制轨迹审计发现：每步末端位置、关节位置和关节速度100%完整，但旧格式全部缺少严格检查点准入所需的：

- `joint_margin`；
- `singularity_sigma`；
- `contact_clear`；
- `recovery_observability`；
- `task_phase`。

因此旧轨迹不能被事后包装成严格安全检查点，尤其不能把“没有报警”解释成“无接触”。审计产物为 `outputs/CHECKPOINT_TRACE_READINESS_LIBERO90_20260925.json`。

在线记录现已增加由公开机器人模型计算的关节限位余量和末端平移雅可比最小奇异值。计算失败时显式记录 `unavailable:<异常类型>`，绝不回填安全默认值。无接触、观察质量和任务阶段仍记录为 `null`，等待独立校准证据源。在线脚本覆盖前备份为 `monitoring_main.pre_checkpoint_kinematics_20260925.py`，并已在LIBERO Python 3.8环境通过语法检查。
