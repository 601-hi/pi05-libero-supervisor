# 重规划后“仅新颖性控制”阶段契约（2026-09-30）

## 用户纠正

用户明确指出：新计划不应再进入回退碰撞门，只看它是否相对失败计划发生实质变化。v10 episode 2 虽然接受了 changed 计划，随后监督器再次报警并重新进入复杂回退，新的回退候选又被碰撞门全部拒绝；从系统效果看，相当于新计划仍被旧回退规则迅速掐断。

## 修正后的权限边界

1. **回退阶段**：JOIN/REPLAY 动作继续经过碰撞硬门；
2. **重规划交接点**：完整10步预测动作块只经过新颖性门；
3. **变化计划执行窗口**：按正常 `replan_steps` 安装动作（每个chunk当前5步），并给予默认25个策略动作的试运行窗口；双专家和视觉继续计算并记录，但不得清空动作队列、请求外部回退或截短动作块；
4. **指令硬门仍保留**：归一化动作越界等第一层指令安全问题仍可立即拒绝；“只看新颖性”不等于执行非法指令；
5. **窗口结束后**：恢复正常双专家和视觉控制权限。碰撞门仍只在之后真正进入回退时作用，不能筛选新计划本身。

这种设计没有永久关闭监督，而是用一个明确、有限的阶段窗口避免旧失败证据和回退启发式污染新计划。

## 实现

- `SupervisorRuntime.begin_novelty_only_window(steps)` 建立有界窗口；
- `observe_step` 在窗口内仍生成、融合并记录事件，但不调用恢复控制器、不清空队列、不请求外部恢复、不截短动作块；
- 日志新增 `novelty_only_control_suppressed`；
- `monitoring_main.py` 对 changed/证据不足但获准的新计划恢复默认5步执行时域，而不是继承恢复阶段的1步时域；
- 监控主循环不会用窗口内的 shadow 报警生成新恢复上下文；
- 窗口逐实际执行步递减，结束后自动恢复正常权限。

## 本地验证

- 变化计划窗口内连续出现 stall：事件仍可见，但队列不被清空、恢复状态不变化；
- 窗口结束后的下一次 stall：正常重新获得控制权限；
- novelty-only 窗口内的非法动作：仍被 instruction guard 拒绝；
- 三个运行文件均通过 Python 语法检查；两个新增行为测试直接执行通过。
