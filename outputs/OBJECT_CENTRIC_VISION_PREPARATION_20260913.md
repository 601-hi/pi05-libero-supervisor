# 物体中心视觉分支：无卡准备阶段记录（2026-09-13）

## 目的与边界

执行监督层的视觉分支不再重复判断“末端有没有按动作移动”，而是回答运动学双专家回答不了的问题：物体是否仍在夹爪中、是否意外滑落、释放时是否已进入语言指定目标、目标是否因遮挡而暂时不可判定。

本阶段没有宣称视觉识别器已经训练完成。已完成的是数据入口审计、信息防火墙、物体关系接口和与具体分割模型解耦的几何后端。真正把 RGB 图像变成 object/target/gripper mask 的感知模型仍属于下一 GPU 阶段。

## 为什么废弃旧视觉 MLP 路线

旧实验允许 task one-hot、translation scale 等变量进入视觉模型。这会让模型学习任务背景或实验条件，而不是从图像验证物体结果；即使测评分数提高，也不能证明跨任务的视觉监督能力。因此新视觉分支只允许：

- 当前及历史 agent-view / wrist-view RGB；
- 自然语言目标；
- 因果时刻与不含结果答案的动作索引；
- 由图像估计出的物体、目标和夹爪关系。

明确禁止输入 task ID、suite ID、成功标签、奖励、扰动开关或 scale、仿真接触真值、物体真值位姿、EEF/关节真值。动作仅用于时序对齐或描述意图，不能把实验标签伪装成动作特征。

## 数据审计结果

- 检查视觉 sidecar：115 个；图像形状及 action index 对齐全部通过。
- 发现 5 个跨 suite 文件名碰撞，全部从当前视觉清单排除，不能静默选取其中一个。
- 保留 110 个唯一 episode。
- 按每 20 个动作抽取一帧，得到 1146 条待标注/伪标注记录。
- 每条记录只暴露图像路径、帧号、视角和官方 goal language。

对应机器可读产物：

- `OBJECT_VISUAL_SIDECAR_AUDIT_ALL_20260913.json`
- `NATURAL_STAGE_GOAL_LANGUAGE_20260913.json`
- `OBJECT_RELATION_ANNOTATION_MANIFEST_20260913.json`

## 已实现的可解释几何层

`vla_supervisor/object_relations.py` 接收三个二维布尔掩码：object、target、gripper，并输出：

- 三者在图像中的面积比例；
- 物体掩码落入目标掩码的比例；
- 物体质心是否位于目标包围框内；
- 夹爪与物体掩码边界的精确像素距离；
- 图像对角线，用于把像素距离归一化以适配不同分辨率。

这层只做几何计算，不读取任务标签，也不访问仿真内部状态。它将“如何得到掩码”和“如何根据空间关系判断结果”分离，因此之后可公平替换零样本分割器、微调分割器或人工标注掩码。

## 与结构化结果监督器的连接

此前的 `StructuredObjectResultMonitor` 接收 object_visible、target_visible、gripper_object_contact、object_in_target、release 及 confidence。新的几何层为其中的可见性、接近/接触和目标包含关系提供可解释观测；时间状态机再结合动作历史区分：

- 正常搬运与正常释放；
- 运输中物体消失或与夹爪分离（unexpected drop）；
- 释放后物体未进入目标（released outside target）；
- 遮挡、目标不可见或感知置信度不足（object ambiguous）。

模糊状态只请求更多证据，不直接触发重规划；只有经过时间一致性确认的物体结果异常才进入执行异常事件。

## 验证

新增三个合成掩码测试，覆盖目标包含、夹爪邻接、物体缺失和形状不匹配。服务器监督器测试集共 18 项，全部通过。

## 下一阶段（需要 GPU）

在冻结的 1146 帧清单上比较候选开放词汇检测/分割后端，先做盲化人工抽查，再选择模型。评价重点不是任务成功率，而是 object/target/gripper 的可见性、遮挡拒判、目标包含和接触近似的准确度，以及跨 suite 表现。模型选择完成前，不把任何视觉输出接入自动报警或重规划。
