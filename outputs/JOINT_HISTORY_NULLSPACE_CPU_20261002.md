# 历史关节构型零空间回退 CPU 节点（2026-10-02）

## 关键审计

历史数据早已完整保存七维`joint_pos`：JOIN目标为`HistoricalJoinState.joint_pos`，每个REPLAY参考为`ReverseReplayReference.joint_target`。此前在线回退只读取历史末端位置/姿态，关节目标没有进入实际控制，所以可能出现末端接近历史轨迹而link5—hand腕部构型仍错误。

v22末端冻结审计支持这一点：回退末尾目标是历史action61，当前末端距该历史点约18.17 mm；但七关节L2误差仍有0.1586 rad，单关节最大误差0.0975 rad（约5.59°）。因此即使继续减小末端距离，腕部仍有独立的构型误差值得控制。

LIBERO当前动作接口是`OSC_POSE`，不能把七维关节差伪装成现有七维动作（现有七维是6D末端增量加夹爪）。直接写MuJoCo `qpos`会跳过控制器与动力学，禁止采用。

robosuite OSC提供公开的`update_initial_joints()`接口，其控制律通过零空间力矩把关节姿态拉向指定构型，同时保持末端主任务。因此v23采用可迁移的混合控制：末端PID继续追踪历史位置/姿态，OSC零空间目标改为同一历史点的七维关节构型。它不是七关节独立位置控制；在7自由度机械臂执行6D末端任务时，主要修正冗余零空间构型，但正适合缓解当前link5—hand腕部净空问题。

## 安全边界

候选预测同步把历史关节目标传给阻尼IK的零空间项，然后仍接受完整关节插值扫掠碰撞门。每次历史参考变化都会更新零空间目标；进入重规划、碰撞拒绝或安全停止时，立刻把OSC零空间目标重置为当前真实关节角，防止历史姿态力矩泄漏到π0.5阶段。功能由`--args.supervisor-joint-history-control-enabled`显式开启，默认关闭，便于与v22严格消融。

日志新增当前关节到历史目标的L2误差及动作后真实关节误差。`OnlineRollbackCursor.active_target_joint`的定向测试已加入，本地静态编译通过。无卡实例连接不稳定曾造成一次新测试配旧文件的单项失败；按SHA-256确认文件重传成功后，三个相关测试文件完整远端回归为123 passed，证明该失败属于同步中断而非算法缺陷。
