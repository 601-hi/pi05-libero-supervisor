# 扩大自然轨迹测试集：无卡准备阶段（2026-09-18）

## 为什么必须扩大

冻结融合器在seed35上检出6/6条失败，但6个独立失败样本对应的95% Wilson区间仍约为60.97%至100%。这只能证明方法值得继续验证，不能证明检出率已经稳定。扩大数据时，以episode为主要独立统计单位，并按suite、task和seed报告分层结果；同一episode里的多个窗口不能伪装成多个独立样本。

## 预注册采集矩阵

主计划共240条自然执行episode：development(seed36)、model-selection(seed37)、sealed-final-test(seed38)各80条。每层覆盖LIBERO-Spatial、Object、Goal和LIBERO-90；每个suite预先固定5个task，每task运行4次。任务集合在运行前写死，不能根据运行结果挑选。

- development允许拟合和查看错误案例；
- model-selection只用于选定一个模型、阈值和时序规则；
- sealed-final-test在冻结前禁止查看模型得分和个案；
- 若seed37+38中自然失败少于50条或正常少于100条，只能按预注册规则用相同矩阵追加seed39。是否追加只能看标签数量，不能看模型表现。

## 多事件而非单一极端窗口

旧流程每条轨迹只选最低response窗口，长轨迹因为尝试次数多，更容易产生极端值。初版尝试每条3个事件且间隔20步，但25/120条短轨迹无法提供任何不重叠对照，且缺失集中在成功的Spatial任务，会引入新的选择偏差。因此在新数据采集前冻结为每条episode选择2个相隔至少10步的低响应事件，并在同一轨迹寻找阶段和指令路程相近的高响应对照。选择过程不读取success、reward、语言或物体身份。

seed34现有120条轨迹在冻结规则下得到240个候选事件和240个匹配对照，120/120条episode均有完整的一对一对照。初版360事件/177对照仅保留为规则选择审计，不用于后续拟合。

## 存储与执行保护

当前数据盘仅剩约13GiB。按历史约18.5MiB/episode估算，240条约需4.34GiB；运行脚本在每层开始前要求至少8GiB可用空间、拒绝覆盖已存在trace、拒绝重复运行已完成层，并且绝不自动删除旧数据。若空间预计低于5GiB，应停机而不是继续采集。

## 统计目标

至少需要在拟合数据之外累计50条自然失败与100条正常episode，仍需报告Wilson置信区间和跨task/seed离散程度。若达不到数量，只能明确称为初步结果。局部异常还需用恢复收益标注，不能把最终success简单等同于整条轨迹正常。
