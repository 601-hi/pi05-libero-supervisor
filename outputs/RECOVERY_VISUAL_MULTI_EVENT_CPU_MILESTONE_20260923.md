# 恢复视觉多事件 CPU 节点（2026-09-23）

## 为什么重做事件协议

首次闭合并不等于首次建立物体控制。三条自然失败开发轨迹共有 18 次夹爪由开到闭的转换：task31 为 1 次，task58 为 7 次，task85 为 10 次。旧视觉脚本只跟踪每条轨迹的第一次闭合，会把 task85 后续可能真正抓住白杯的事件全部遗漏，并可能把第一次空抓错误地固化为整条轨迹的诊断。

本节点建立了逐闭合事件协议。事件只由夹爪开到闭的转换选择，不读取成功标签、任务语言、语义检测或最终结果；每个事件保存闭合前 15 帧和闭合后 40 帧。事件窗口允许重叠，因为相邻闭合仍代表不同的因果假设，但统计评估必须以 episode/task/seed 聚类，不能把 18 个事件当作 18 条独立轨迹。

## 新状态机的保守规则

1. 语义目标匹配不能单独证明物理抓取。
2. 只有固定视角出现独立世界运动且腕部候选形成稳定附着，才能建立 `control_established`。
3. 已建立物理控制后，语义不匹配才可输出 `wrong_object_control`。
4. 完整观察窗内固定视角无运动且腕部无附着，才能输出可被后续闭合推翻的 `empty_grasp_or_miss`。
5. 控制状态持续到明确释放或丢失；不能因下一事件证据暂缺而自动清空。
6. 只有曾建立物体控制，才允许判断目标关系是否满足。
7. 冲突或缺失证据一律输出 `pending`，当前阶段只做诊断，不直接生成机器人动作。

## 第一批语义冲突审计

Grounding DINO 与 Florence-2 的框重叠只能作为跨模型候选，不能当作校准后的目标身份概率。首次闭合的固定视角结果为：

- task31：一个跨模型重叠候选，但仍需物理确认；该事件固定视角没有持续物体运动。
- task58：两个 DINO 候选都与 Florence 候选高度重叠，属于跨模型多解；固定视角却存在约 16.74 像素持续运动，说明确有物体被扰动，但目标身份不明。
- task85：一个跨模型重叠候选，但首次闭合没有持续世界运动；该轨迹还有九次后续闭合，不能用首次闭合下整条轨迹结论。

这一结果也揭示了“两个模型一致”的限制：两个模型可能共同定位到显眼的托盘、容器或背景区域。检测器分数是各自模型的置信度，不是 `P(身份正确)`；跨模型 IoU 也只是候选提议，不是物理同一性证明。

CPU 阶段已经到达当前证据所允许的边界。下一步必须用 GPU 对 18 个事件分别运行腕部和固定视角双向 SAM2，再离线判断：哪一次闭合真正建立控制、何时丢失、是否控制错误对象，以及放置关系为何未满足。密封的跨套件最终测试仍保持未打开；开发结果冻结后才允许进入成对闭环验证。
