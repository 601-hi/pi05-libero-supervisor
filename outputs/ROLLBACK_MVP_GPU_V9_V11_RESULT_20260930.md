# 回退 MVP 与重规划新颖性门 GPU v9--v11（2026-09-30）

## 结论先行

本轮把“检测—历史轨迹邻域—重新观察—新计划比较—重复则更早回退”真实跑通，但没有提高最终 LIBERO 成功数：严格旧版与 MVP 都是 1/5。MVP 在 2/5 回合到达重规划，而旧版相应回合仍停在精确回放或碰撞门；新颖性门能够区分重复与变化，并在修复后有界地拒绝重复计划。剩余失败主要来自 JOIN 碰撞候选耗尽或不收敛，以及 π0.5 即使产生变化计划也未完成任务。

因此这是“框架贯通与失败位置前移”的正结果，不是“端到端成功率提升”的正结果。

## v9：发现执行时域与判断时域混淆

v9 首次运行中，恢复状态把安全执行时域压缩为1步；新颖性门错误地也只比较了这1步，因此三次返回 `too_few_aligned_steps` 并 fail-open。该轮不用于评价新颖性门效果，但揭示了重要接口原则：

> 可以只执行新计划的第1步，但必须用 π0.5 输出的完整动作块判断计划是否发生实质变化。

修复后，执行仍保持短时域，比较改用完整10步动作块；接受变化计划后同时清空旧失败上下文，后续失败建立新参照。

## v10 暴露的层级上限 bug

episode 0 在重复计划达到最大层级后只记录了 `repeated_replan_no_deeper_checkpoint`，却没有把外部恢复端口真正切到 `SAFE_STOP`，导致层级错误地继续增长到7。修复方式不是扩大预算，而是：即使达到层级上限，也显式创建并领取恢复请求，随后以 `safe=False` 完成，使端口进入不可继续执行的安全停止状态。

## v11：单回合边界验证

只重跑 episode 0 的 strict/MVP 配对：

- 介入前82步严格一致；
- 新颖性门连续三次比较完整10步动作块；
- 三次均判为 repeated；
- 层级严格为0、1、2；
- 达到三级总预算后以 `repeated_replan_no_deeper_checkpoint` 停止；
- 未执行重复的新计划，未再出现3到7的越界循环。

两组均失败，因此此修复证明的是边界与控制正确性，不是任务成功收益。

## 当前瓶颈与下一主线

1. episode 1/4 仍未进入重规划，分别受碰撞候选耗尽和 JOIN 不收敛限制；
2. episode 2 已进入重规划且计划变化，但新轨迹随后被碰撞门停止，需要区分真实危险与策略接触任务中的可接受交互；
3. episode 0 表明同一观察下 π0.5 可能连续生成高度相似计划；更早锚点不是无限可用，达到上限必须停止；
4. 最终成功率未提升，不能继续只优化回退局部指标。下一步应以完整任务结果为导向，优先完成“变化计划后的阶段语义监督与可接受接触边界”，再做端到端小规模配对。
