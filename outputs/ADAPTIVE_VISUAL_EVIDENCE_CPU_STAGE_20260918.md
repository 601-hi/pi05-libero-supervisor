# 自适应视觉证据CPU阶段（2026-09-18）

## 本阶段解决的问题

上一GPU阶段证明两个问题：旧EEF像素投影跨相机域失效，固定1.5像素运动门又远高于实际可见残差。本阶段不训练新分类器，而是先把域校验和相对测量做成可测试接口，避免错误标定或理想化阈值进入监督器。

## 相机域硬校验

`GripperPixelProjector`新增可选`ProjectionDomain`，由相机ID、图像尺寸和预处理指纹组成。在线调用必须通过`project_for_domain()`逐项精确匹配；否则不返回像素坐标，只返回`camera_id_mismatch`、`image_shape_mismatch`或`preprocessing_mismatch`。历史标定仍可加载以复现实验，但因为没有域元数据，安全入口固定返回`legacy_unbound`并弃权。

投影拟合脚本同步支持写入三项元数据，而且禁止只提供其中一部分。该机制不会证明标定数值正确，但能阻止已知不同的相机和预处理管线静默共用标定。

## 防污染自适应运动基线

新增`AdaptiveMotionBaseline`。输入为静止背景补偿后的候选运动像素量，内部先做`log(1+x)`，再用滚动中位数与MAD建立参考。当前样本总是先评分、后选择性更新；只有调用者明确声明可更新，且背景置信度达标时才进入参考，报警、恢复或证据未知阶段不得污染基线。

输出包括运动下降和运动过量的稳健z分数，但不是概率。视觉后果评分器已可把这些值写入`relative_motion`诊断字段；独立运动概率和阻塞概率在没有冻结校准器时仍保持`None`。

## 单案例机制审计

为避免依赖不稳定候选ID，每一步取全部候选中最大的中位背景残差，表示该帧是否至少存在一个可见独立后果。动作40至58的18步仅用于建立案例内参考；动作59至129的71步只评分、不更新。

- 参考段集合最大残差：p10 0.144、median 0.215、p90 0.336像素；
- 卡滞段：p10 0.0197、median 0.0358、p90 0.0575像素；
- 卡滞运动下降z：p10 1.775、median 2.040、p90 2.241；
- 57.7%卡滞步超过2个稳健尺度，没有一步超过3。

这只是机制可行性，不是阈值选择。它说明相对近期正常运动比固定像素门更适配当前画面，同时证明武断设`z>3`会漏掉整个案例。阈值、2-of-3与3-of-5必须在多条独立开发轨迹上联合比较，最终测试集不得参与。

## 下一GPU数据矩阵

下一次开卡不再只跑一个已知失败。最小开发矩阵应包含多个suite/task/seed，并覆盖：自由空间正常运动、正常接触但低位移、成功带动物体、空抓、固定环境卡住、抓取后掉落和恢复成功/失败。每条保存固定与腕部RGB、动作、EEF、关节状态、双专家状态、视觉调用原因和结果；按episode分组，正常/异常窗口不能随机拆散到训练与验证两侧。

相机域先采少量独立标定轨迹并冻结预处理指纹。最终测试episode完全隔离。视觉只在双专家模糊、接触窗口或长期低进展时触发，以控制SAM2侧车开销。
