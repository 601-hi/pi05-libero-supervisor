# 几何目标测量无卡里程碑（2026-09-20）

## 本阶段解决的问题

目标进展监视器此前缺少可信的夹爪图像坐标。旧方法以20个人工网格点拟合EEF xyz到像素的二次映射，既没有绑定相机域，也把动作前图像与`eef_pos_after`配对。GPU烟测加入逐帧内外参、EEF位姿与夹爪状态后，本阶段审计这些数据能否直接形成安全测量。

## 坐标约定错误及纠正

动作前后EEF错位只造成中位0.46像素、p90 0.89像素位移，不是旧投影尾部误差的主因。第一轮复算得到中位37.07像素、p90 89.72像素，并一度怀疑跨场景外参。随后GPU预注册采集显示Spatial task 0、3、4的相机内外参完全一致，源码也确认`robot0_eef_pos`来自`grip_site`。真正错误是图像纵轴被重复翻转：robosuite几何投影的纵坐标已经对应正向显示，保存策略图像后只需补偿水平轴。

改为`flip_x=True, flip_y=False`后，旧20个人工网格点的物理投影误差为中位8.59像素、p90 18.28像素、最大20.50像素；此前经验二次映射的留一结果为中位6.91、p90 20.60、最大23.68像素。物理方法没有用这20点拟合参数，尾部误差反而略低，但翻转约定是在观察这些点后确定的，因此这20点不能再充当独立测试或误差界。机器可读记录为`PHYSICAL_PROJECTION_WAVE1_AUDIT_20260920.json`。

这次纠错说明：三维点处于视野内、轨迹又随机械臂运动，均不足以证明像素约定正确；必须检查明确的物理标志点和轴方向。

## 新的安全入口

新增`vla_supervisor/geometry_measurement.py`：

- 四元数顺序必须明确为xyzw或wxyz，禁止猜测；
- EEF到工具点的局部刚体偏移属于小型载体标定；
- 每帧使用对应相机外参；
- 相机ID、内参、保存尺寸和翻转约定生成不可随意改名的域指纹；
- 工具点缺少独立误差半径或验证ID时，只返回诊断像素，不生成可信测量。

新增`goal_progress_adapter.py`把几何投影、目标点与进展监视器连接起来。只有夹爪点和目标点均经可信验证、目标身份一致、同动作索引、同相机域且使用固定相机几何时，才能形成带误差界的二维接近距离。任何缺失、假框、跨帧、跨域或移动相机原始距离都输出unknown，不会触发恢复。

采集器最终升级为geometry schema v3，显式记录`pre_action`、`robot0_grip_site`、`xyzw`、`opencv_camera_to_world`以及`projection_flip_x=True/projection_flip_y=False`。旧v1/v2烟测会被新契约拒绝。

## 验证

几何、测量、进展适配及sidecar定向测试64项通过。排除根目录下重复隔离快照后，服务器主测试集合`tests + cross_suite_generalization`为273项全部通过。直接从仓库根运行无排除pytest会因`goal_progress_validation_20260920`是同名测试快照而产生模块名冲突；这是测试发现布局问题，不是实现回归，未删除该验证快照。

## 数据与资源治理

按用户要求删除不再使用的Qwen3-VL-2B-Instruct权重目录及锁缓存，保留试验输出、人工复核和审计结论。释放约4.0GiB，数据盘可用空间由5.7GiB增至9.7GiB。删除的模型权重不能本地恢复，但可重新下载。

## GPU续接结果与下一主线

schema v2在Spatial task 0、3、4共三条成功轨迹上通过契约；三者相机模型指纹与外参一致，由此否定了先前的跨场景解释。修正纵轴约定后，schema v3又在task 3成功轨迹的97帧上通过契约。五帧叠加中红色`grip_site`投影随姿态始终落在夹爪操作中心附近。可视化为`GEOMETRY_V3_TASK3_EEF_OVERLAY_20260920.png`。策略服务随后关闭，端口和GPU进程均为空。

几何分支仍保持shadow，因为尚缺新的独立标注来冻结误差半径，目标物体定位也仍需可信验证。下一主线不再继续微调夹爪投影，而是使用现有动作双专家与保守视觉后果分支进入端到端监督—重规划成对试验，以LIBERO成功率、破坏率与额外步数为最终裁决。

本阶段没有新的异常检出率或LIBERO成功率声明。
