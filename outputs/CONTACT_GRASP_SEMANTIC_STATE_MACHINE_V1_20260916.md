# 接触—抓取—身份—保持视觉诊断状态机 v1（设计候选）

## 动机

现有逐步视觉链主要从“已建立夹持”开始，判断物体是否继续随夹爪运动。用户指出这遗漏了更早也更关键的因果问题：夹爪是否发生接触、接触的是可动物体还是固定背景、是否真正带动物体，以及被带动的物体是否符合语言指令。该建议纳入下一版设计，但不改变已经验证过的动作双专家职责，也不使用单一视觉信号直接覆盖明确动作异常。

## 信息分工

1. **动作双专家**：判断指令—末端响应是否属于已知正常、已知异常、分布重叠或低支持。低支持只表示“不知道”，不等于接触。
2. **固定相机静止背景场**：估计世界静止共识并寻找相对背景独立运动的候选；同时判断接触后局部物体是否仍与背景保持一致。
3. **腕部相机与夹爪状态**：判断夹爪接近、闭合以及候选是否相对夹爪建立附着。
4. **语义核验器**：只在物理受控候选已经形成后，回答“被控制对象是否符合任务语言”，不能反过来决定物理接触是否发生。
5. **时序融合器**：区分瞬时遮挡、可恢复滑动、持续空抓、固定障碍受阻、错误物体控制和正确抓持。

## 候选状态机

```text
FREE_MOTION
  | 动作响应异常/低支持 + 夹爪接近或闭合 + 局部背景/候选证据
  v
CONTACT_SUSPECTED
  |-- 后续无独立运动候选，末端持续受阻 --> FIXED_OBSTACLE_OR_JAM
  |-- 后续无附着候选，末端不再受阻 -----> EMPTY_GRASP_OR_MISS
  |-- 出现随夹爪运动的候选 -------------> OBJECT_CONTROL_ESTABLISHED
                                               |
                                               +-- 语义不符 --> WRONG_OBJECT_CONTROL
                                               +-- 语义相符 --> TARGET_CONTROLLED
                                                                      |
                                                                      +-- 持续附着 --> HEALTHY_TRANSPORT
                                                                      +-- 短暂失稳后恢复 --> TRANSIENT_UNCERTAINTY
                                                                      +-- 持续失稳 --> OBJECT_LOSS_RISK
```

## 因果判据草案

在时刻 `t`，仅当动作层不是明确正常，且处于接近/闭爪阶段，才允许形成接触假设：

\[
H_t^{contact}=g(z_t^{action}, r_t^{bg}, d_t^{gripper}, q_t^{gripper}, h_{t-k:t})
\]

其中 `z_action` 是双专家四态和可靠性，`r_bg` 是相对静止背景的局部残差，`d_gripper` 是夹爪与候选的图像距离或重叠，`q_gripper` 是闭合状态，`h` 是短时历史。不能使用“低可靠性”单项直接判定接触。

接触后观察窗口内：

- 若没有候选脱离静止背景，且末端响应持续受抑制，形成“固定障碍/卡住”证据；
- 若出现相对背景独立运动，并在腕部视角与夹爪保持稳定关系，形成“受控物体”证据；
- 若候选移动但不随夹爪，保留为推动、碰撞或未知，不能等同于抓取成功；
- 建立物理受控关系后才调用语义核验，避免开放词汇模型先验支配物理判断。

## π0.5 语义复用的边界

复用 π0.5 的视觉—语言表征值得验证，但当前不能直接假设 checkpoint 提供可靠的独立 VLM 问答概率。π0.5 是动作生成模型；需要先确认是否能在不微调、不读取奖励和任务结果的情况下导出对象—语言兼容分数，并与 Florence-2/开放词汇基线比较。如果只能通过动作变化间接推断语义，就不能把它称为独立语义专家。

## 不改变的安全原则

- 明确动作异常不能被视觉“看起来正常”否决；视觉主要解决模糊/未知和故障类型诊断。
- 静止背景用于世界运动参考和候选剪枝，不单独证明碰撞。
- 接触、受控对象身份、任务语义和持物稳定性是四个不同问题，分别评测。
- Wave1—Wave3已经用于设计；本状态机只能在冻结后由新 Wave4 或独立任务前瞻验证。

## 下一步实现顺序

1. 在离线回放中增加 `CONTACT_SUSPECTED` 及固定障碍/空抓的因果观察窗口，不改现有双专家阈值。
2. 为每次闭爪事件输出结构化时间线：接触假设、独立运动出现、腕部附着建立、语义核验、附着丢失/恢复。
3. 先用人工匿名审计建立接触与受控物体真值，再评价各层，避免只用任务成功标签。
4. 单独做 π0.5 语义可读性实验；失败时保留可替换语义接口，不阻塞物理状态机。
5. 冻结代码、阈值和清单后扩大 Wave4，报告接触检出、固定障碍/空抓区分、受控对象识别、语义正确率、持物故障检出和最终轨迹级误报。
