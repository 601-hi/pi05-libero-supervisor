# 闭环监督—重规划 CPU 集成节点（2026-09-20）

## 本阶段目标

停止继续单独优化视觉局部指标，把已经冻结的执行双专家、通用干预状态机、策略动作队列和最终 LIBERO 成败评测接成一条可运行主线。该阶段不启动 π0.5，只完成代码合并、因果日志、自动实验与离线回归。

## 已完成结构

在线顺序冻结为：

1. π0.5 根据当前公开观测产生动作块；
2. 指令安全门在动作执行前检查动作边界；
3. 动作执行后，冻结的五成员条件双专家输出四态执行证据；
4. 明确执行不一致经时序融合后清空剩余动作块；
5. 默认先执行一个保持动作，再从当前观测重新调用 π0.5；
6. 模糊态只记录并请求证据，不改变动作队列；
7. 策略停滞默认不自动撤退；恢复提示词默认关闭；
8. 恢复预算耗尽则在下一动作前终止 episode，不允许新动作块绕过安全停机。

视觉后果接口保留在同一运行时中，但当前背景运动评分器尚未证明能可靠决定恢复动作，因此首轮闭环只启用冻结执行双专家。这样做是在隔离“动作截断与重新规划是否真的提高成功率”，不是宣称视觉分支已经完成。目标关系与相机 geometry schema v3 仍保存在采集器中，后续可以在同一日志上补充选择性视觉诊断。

## 合并时修复的关键问题

原干预候选脚本具备动作块截断、保持、重规划和安全停止，但早于相机几何修正。现已把它与生产 geometry schema v3 合并，继续记录动作前图像、固定/腕部相机内外参、`robot0_grip_site`、xyzw 四元数以及 `flip_x=True, flip_y=False`，没有退回旧的双轴翻转。

第二个问题是因果分叉时刻。执行不一致是在某个动作完成后才被检测，所以该动作仍属于原策略，不能因为同一条日志带有 `hold_then_replan` 就算成监督器动作。采集器新增 `supervisor_control_epoch_before_action`：只有下一步动作执行前 epoch 已大于零，才认定控制流已经由监督器改变。成对评估由此严格检查分叉前的动作和 EEF 状态完全一致。

## 成对实验与指标

`scripts/run_paired_closed_loop.py`读取冻结计划，对每个身份依次运行：

- baseline：监督器完全关闭；
- control：冻结四态双专家开启，允许清块、保持和重规划。

两臂共享 suite、task、环境 seed、初始状态和 π0.5 固定扩散噪声。计划和manifest在首条轨迹之前写盘；中断后只跳过存在唯一`episode_end`的完整轨迹，禁止根据已见结果改变任务。

结果不再只报检测率，而是逐对分为：

- rescued：baseline失败、control成功；
- harmed：baseline成功、control失败；
- preserved_success：两者成功；
- unresolved_failure：两者失败。

同时报告成功基线中的harm率、失败基线中的rescue率、总步数/推理调用增量、重规划次数，以及分叉前动作与状态是否严格相同。任何因果身份失败都会令`valid_for_causal_claims=false`，该批数据不能用于“监督器造成改善”的结论。

首个冻结Stage-1计划覆盖Spatial、Object、Goal、LIBERO-10四个suite，各选预先固定的偶数task 0/2/4/6/8，共20对；不依据历史成功或失败选择任务，也不注入scale扰动。它是端到端pilot，不是最终统计结论；若看到效果，再用新seed确认而不是回头调这20对。
