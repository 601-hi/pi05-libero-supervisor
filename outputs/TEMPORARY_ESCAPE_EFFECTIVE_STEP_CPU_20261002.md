# 临时逃逸有效步幅审计与 v20 CPU 准备（2026-10-02）

用户质疑逃逸步数过小后，对v19四步逃逸进行指令—末端—关节三层审计。

前两步归一化平移动作范数均为0.06，对应控制器目标位移3 mm，与129个普通REPLAY步的目标位移中位数3 mm相同，因此配置指令本身并不小。但其真实末端位移仅0.293 mm和0.397 mm，低于普通REPLAY真实位移10分位0.472 mm及中位数0.678 mm。后两步因候选缩放为0.5和0.25，目标位移降至1.5 mm和0.75 mm，真实位移仅0.191 mm和0.038 mm。四步真实路径总长不足1 mm。

四个方向的预测自碰净空增益分别约+0.199、+0.197、+0.052和+0.022 mm，真实变化却分别为-0.013、-0.031、-0.018和-0.003 mm。最小碰撞对始终是link5—hand，并非由碰撞对切换制造的假象。结论是单步真实响应太弱，立即按微米级净空变化禁用方向会把控制瞬态误当成方向错误；但也不能据此直接放大单步，因为3 mm目标已经与正常REPLAY相同。

v20保持单步动作和12步独立总预算不变，把反馈改为三步累计探测：同一方向连续执行最多3步，每一步仍重新经过扫掠碰撞门并优先重试direct；三步后按相对该方向起点的累计真实自碰净空判断。累计恶化超过0.1 mm可提前禁用，避免为了凑满三步扩大明显错误运动；三步确有改善则以当前真实净空为新基线继续下一包。这样增加的是可辨识的物理响应长度，而不是关闭安全门或盲目放大动作。

代码静态编译通过，相关回归保持122 passed。下一GPU冻结运行应命名为v20，并与v19比较每个方向的累计三步响应、direct恢复率、最大空间撤离和是否到达10 cm交接门。
