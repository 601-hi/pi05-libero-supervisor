# 当前技术状态与视觉方案决策输入（2026-09-27）

## 1. 项目目标与当前分层

项目目标不是继续微调 π0.5，而是在尽量保持基础策略冻结的前提下构建通用、可审计的监督与纠偏系统：

1. **指令/计划层**：发现动作计划本身没有推动任务目标；
2. **执行层**：判断机器人实际响应是否符合计划，并监测碰撞、卡滞、奇异点等安全风险；
3. **任务结果层**：判断交互对象与环境状态是否向语言目标发展；
4. **恢复层**：按错误机制选择暂停、重观察、局部退让、历史回退、重新规划或安全终止。

当前执行层与机械恢复链已基本贯通，最大的空缺是**任务目标条件下的视觉状态与进展证据**。

## 2. 已验证能力

### 2.1 执行一致性

- 条件正常动力学专家预测在当前状态与指令下的正常响应分布；
- 异常专家描述已知故障响应；
- 融合器区分 normal、known abnormal、unknown abnormal、ambiguous overlap；
- 低可信或跨域输入允许弃权，不把未知伪装成正常或异常；
- 时序门避免将单帧尾部漂移直接升级为干预。

边界：这一层回答“是否照计划运动”，不回答“计划是否正确”。

### 2.2 安全回退

- 三段式历史点准入：早期可信、中段宽松、近期严格；
- 逐碰撞几何体对的候选硬门；
- 直达不安全时生成多方向、多尺度逃逸微步；
- 安全余量低时优先脱险，余量恢复后逐步提高历史汇合权重；
- 6DoF 汇合后按离散历史状态倒序回放，并闭环修正漂移；
- `join` 与 `replay` 使用独立预算；
- 录像叠加 action、状态、目标历史点、候选和预测间隙。

### 2.3 严格配对

同一 π0.5 服务生命周期内完成 baseline/control 配对。首次复杂回退 action 为 55；`[0,55)` 内：

- intended action 最大差异 0；
- executed action 最大差异 0；
- 末端执行前/后位置最大差异 0；
- 关节执行前/后位置最大差异 0；
- 采样噪声哈希序列一致。

因此这是一对有效反事实前缀，而不是仅凭相同 seed 宣称可比。

## 3. 最新端到端结果

任务：LIBERO-90 task 0，语言日志为 `close the top drawer of the cabinet`。

| 条件 | 策略动作 | 回退动作 | 最终成功 |
|---|---:|---:|---:|
| baseline | 400 | 0 | 否 |

- action 55–334：280 步 `join`，汇合至历史 action 21；
- 随后 69 步 `replay`，依次到达 action 18、17、15；
- action 403 后完成倒序回放并重新调用 π0.5；
- π0.5 继续执行，但仍未完成任务；

人工观看配对视频得到重要现象：baseline 与 control 最终都把碗放入抽屉，但都没有成功合上抽屉。该观察来自视频人工审计，不是自动视觉标签。它表明机器人可以较好执行一串物理动作，却长期没有满足语言任务的最终目标。

当前诚实结论：**回退器已证明能够完整工作，但尚未救回任务；主要瓶颈已转移到目标状态监督和回退后的目标定向重规划。**

## 4. 当前视觉模块究竟有什么

已经存在：

- 任务语言到目标实体/关系的规则解析器；
- 固定相机与腕部相机的逐步帧及相机标定 sidecar；
- SAM2 目标身份生命周期与跟踪质量门；
- 静止背景、共同运动和可能受控物体的候选证据；
- 受控物体与任务目标的融合状态；
- `no_progress`、`wrong_object`、`object_lost` 到恢复目标的在线接口；
- 带不确定性的时间进展监视器和低频独立视觉查询入口。

仍然缺失：

- 可部署的任务条件视觉证据源；
- “上层抽屉当前开合程度”这类机构状态测量；
- “碗在抽屉里但抽屉仍开着”这类组合关系判断；
- 目标状态长期不改善时的可靠在线触发；
- 基于未满足目标生成、并对新动作块做反重复检查的重规划机制。

当前生产视觉模式中的目标候选提供器为空，实际只能检查背景健康度。也就是说，接口已经接通，但最重要的传感内容没有真正进入系统。

## 5. 过去视觉试验给出的约束

1. **SAM2不是语义识别器。**它可以维持一个已经正确初始化的目标，但错误框也会被稳定跟踪。
2. **开放词汇框不够可靠。**黑碗、柜体、moka pot、机械臂等存在混淆；框中心也不等于可操作点。
3. **仅看共同运动不够。**它能说明哪个物体可能受夹爪控制，不能说明任务最终关系是否满足。
4. **仅看末端轨迹不够。**成功轨迹也会徘徊、回撤和调整；路径效率与任务进展不是同一变量。
5. **π0.5 latent尚未证明有效。**4×4视觉 latent已能导出，但此前目标定位和变化检测效果不足。
6. **视觉证据必须允许 unknown。**遮挡、身份冲突、相机域不一致或未校准时必须暂停证据，而不是填零或强行分类。
7. **不能使用测试场景特调。**任务差异应通过声明式关系表达，不能写 task ID、固定像素区或对象专属规则。

## 6. 接下来视觉方案要回答的问题

视觉主线不应再局限于“物体是否随夹爪移动”，而应输出：

\[
g_t = P(\text{当前视觉状态满足语言目标}\mid I_{0:t},L)
\]

以及带不确定性的进展：

\[
\Delta g_t = g_t-g_{t-w}.
\]

但第一版不必直接训练一个包办所有任务的黑盒概率模型。建议把语言目标解析成通用关系族，再为关系族提供可校准测量：

- `object_in_region`：物体进入容器/区域；
- `object_on_support`：物体放到表面；
- `mechanism_state`：抽屉、门、旋钮等机构状态改变；
- `object_controlled`：夹爪是否稳定控制目标；
- `goal_stable`：目标关系是否持续满足而非瞬时出现。

视觉证据只报告状态、误差界和可观测性；时间监视器负责判断改善、停滞或倒退；恢复器根据诊断决定重观察或重规划。这样可以替换视觉模型而不重写状态机。

## 7. 三种候选视觉路线

### 路线 A：端到端 VLM 直接判断目标是否完成

输入任务文字和当前/历史图像，输出完成、未完成、未知及理由。

- 优点：最快接入，可覆盖多种关系；
- 风险：自报置信度不校准、容易利用场景背景、难定位错误来源；
- 合适角色：低频提议器或重规划语言证据，不宜单独控制机器人。

### 路线 B：结构化关系测量

先定位目标实体/机构，再测量与任务相关的状态，例如抽屉开合比例、物体—容器掩膜关系。

- 优点：可解释、可校准、容易做时间进展；
- 风险：不同关系族需要不同测量适配器；开放世界覆盖较慢；
- 合适角色：主安全证据和在线进展监督。

### 路线 C：结构化语言解析 + 候选定位 + 跟踪/几何测量 + 可选低频复核

任务语言与 BDDL 谓词先确定目标关系；成熟检测器或其他候选源负责提出实体候选，SAM2/几何方法只保持已确认身份并形成连续状态量。外部 VLM 可在阶段切换或冲突时低频复核，但 π0.5 主干本身不会直接生成语言解释，不能把它虚构成问答接口。

- 优点：兼顾语义覆盖与连续测量，复用现有生命周期、静止背景和跟踪代码；
- 风险：初始化错误仍会传播，必须有身份冲突、跨视角和弃权门；
- 当前最符合已有工程基础，可作为优先候选。

## 8. 最小有效视觉闭环建议

为优先证明整套系统有效，而不是继续无限打磨组件，建议冻结以下 MVP：

1. 语言解析器输出目标关系，不读取 task ID；
2. 结构化语言解析器给出关系图；开放词汇检测或其他候选源只负责候选初始化，不独立证明身份正确；
3. 固定相机对目标状态进行连续测量，SAM2只保持已确认身份；
4. 同一关系、同一相机域内计算带误差界的进展；
5. 执行层正常但目标状态连续不改善时，触发 `goal_no_progress`；
6. 重规划提示明确指出未满足关系，而不是只说“重新观察”；
7. 新动作块若与失败前动作/视觉后果高度重复，则拒绝并再次请求规划；
8. 仿真对象位姿和任务 success predicate只用于离线真值与评估，不进入在线监督输入。

第一轮只要求在若干开发任务上证明：目标状态可观测、停滞能被识别、错误重规划能减少，并立即进行同服务 paired LIBERO 端到端测试。达到最低可用后停止视觉细调，回到整体成功率、误伤率和恢复成本评价。

## 9. 暂缓事项

- 不修改当前回退历史点选择策略；“保留近目标视角”记录为后续优化。
- 不继续围绕回退微步调权重，除非新证据显示安全或收敛失败。
- 不把仿真器内部抽屉关节、物体位姿作为在线视觉输入。
- 不重新启用已证明效果不足的 Qwen/latent 方案，除非有新的、预注册的增量假设。
- 不在当前单条 task 0 视频上手写专用规则。

## 10. 已知日志缺陷

多次恢复尝试时，`episode_end` 中游标的 `rollback_join_steps` / `rollback_replay_steps` 会被第二次 `begin()` 重置，导致最终显示 0，虽然累计 `rollback_executed_steps=349`。原始 proposal 事件足以重建第一次尝试的 280+69 步，但汇总字段需要在下一 CPU 阶段改为 episode 累计和 per-attempt 列表。该问题影响汇总可读性，不改变已执行轨迹或配对成功判定。
